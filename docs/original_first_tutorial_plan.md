# 원본 우선 RAG FastAPI 튜토리얼 재작성 계획

## 목표

이 프로젝트의 목표는 튜토리얼처럼 보이는 샘플 앱을 만드는 것이 아니다.

목표는 기존 원본 앱과 같은 결과물을 다시 만들 수 있게 하는 것이다. 최종 산출물은 원본 앱과 같은 앱 구조, FastAPI 구조, RAG 구조, 웹 화면 구조, 전국 지역 데이터, 관광 상담 흐름을 가져야 한다.

튜토리얼은 그 산출물을 만드는 과정을 설명하는 교재다. 따라서 튜토리얼 설명은 문서에만 있어야 하며, 사용자가 실제로 보는 웹 화면이나 API 응답에는 튜토리얼용 표현이 들어가면 안 된다.

## 원본 앱 기준

이 문서에서 말하는 원본 앱은 기존 `chatbot_rag` 프로젝트다.

작업 문서와 명령에서는 원본 앱 루트를 `<original_app_root>`로 부른다. 작업자는 자신의 환경에서 `<original_app_root>`를 기존 `chatbot_rag` 프로젝트 루트로 바꿔 읽고 비교한다.

원본 앱의 기준 파일은 다음이다.

```text
<original_app_root>/
├─ app/
│  ├─ main.py
│  ├─ api/
│  │  ├─ deps.py
│  │  └─ routes/
│  │     ├─ chat.py
│  │     ├─ documents.py
│  │     ├─ health.py
│  │     └─ tourism.py
│  ├─ core/
│  │  ├─ config.py
│  │  └─ logging.py
│  ├─ repositories/
│  ├─ schemas/
│  ├─ services/
│  └─ utils/
├─ frontend/
│  └─ web/
│     ├─ index.html
│     ├─ app.js
│     ├─ styles.css
│     └─ option_flow_builder.js
├─ data/
│  └─ processed/
│     ├─ tour_area_codes.json
│     └─ tourapi_bigdata_region_codes.json
├─ scripts/
├─ tests/
├─ requirements.txt
├─ docker-compose.yml
├─ run_tourism_debug_tunnel.sh
└─ run_tourism_release_tunnel.sh
```

원본 앱에서 기준으로 삼는 기능 표면은 다음이다.

- FastAPI 앱 진입점과 라우터 구조
- RAG 서비스 계층과 의존성 조립 구조
- 관광 상담 서비스 계층
- 전국 지역 코드와 시군구 해석
- `/tourism-ui/` 웹 화면
- Quick Tunnel 실행 스크립트
- 평가, 캐시, 로그, 회귀 테스트 흐름

복사하지 않을 원본 항목은 다음이다.

- `.env` 실제 비밀값
- 로컬 SQLite 데이터베이스
- Chroma 런타임 저장소
- `data/generated/` 실행 부산물
- `.venv`
- `__pycache__`
- 개인 환경에 묶인 로그와 임시 파일

정리하면, 원본 앱은 `chatbot_rag`이고 새 프로젝트는 그 결과 표면을 `project_template` 안에 재현한다. 튜토리얼 문서는 이 재현 과정을 설명한다.

## 핵심 원칙

1. 산출물은 원본 앱과 같아야 한다.
2. 문서는 산출물을 만드는 과정을 초급자가 따라 할 수 있게 설명해야 한다.
3. 웹 화면은 실제 사용자용 관광 상담 앱이어야 한다.
4. API 응답의 사용자 표시 문구에는 `Chroma`, `top_k`, `lookup_mode`, `fallback`, `debug`, `parity` 같은 내부 구현 용어를 노출하지 않는다.
5. 내부 진단 정보는 개발 모드나 로그, 테스트, 문서에서만 다룬다.
6. 지역 데이터는 일부 샘플이 아니라 전국 광역 지역과 시군구를 기준으로 한다.
7. 원본 앱의 구조를 먼저 맞춘 뒤 문서화한다. 문서를 먼저 쓰고 임의 산출물을 맞추지 않는다.

## 최종 산출물 기준

### 앱 구조

최종 `project_template`는 원본 앱의 주요 구조를 따른다.

```text
project_template/
├─ app/
│  ├─ api/
│  │  ├─ deps.py
│  │  └─ routes/
│  ├─ core/
│  ├─ repositories/
│  ├─ schemas/
│  ├─ services/
│  └─ main.py
├─ data/
│  ├─ eval/
│  ├─ processed/
│  └─ generated/
├─ frontend/
│  └─ web/
├─ scripts/
├─ tests/
├─ requirements.txt
└─ README.md
```

튜토리얼을 위해 구조를 단순화하지 않는다. 초급자 설명은 문서에서 단계적으로 풀어 쓴다.

### FastAPI 구조

FastAPI는 원본과 같은 역할 분리를 가져야 한다.

- `app/main.py`: 앱 생성, 미들웨어, 라우터 등록, 정적 웹 UI 연결
- `app/api/routes/health.py`: 상태 확인
- `app/api/routes/chat.py`: 일반 RAG 채팅
- `app/api/routes/tourism.py`: 관광 상담, 지역 목록
- `app/api/routes/documents.py`: 문서 조회
- `app/api/deps.py`: 서비스 의존성 조립
- `app/core/config.py`: 설정 로딩
- `app/schemas/*.py`: 요청과 응답 형식
- `app/services/*.py`: RAG, TourAPI, 관광 상담, 카드 변환, 의도 분류
- `app/repositories/*.py`: 저장소 접근

### RAG 구조

RAG 구조도 원본 기준을 따른다.

- 문서 로딩
- 텍스트 분할
- 임베딩 생성
- 벡터 저장소 검색
- 프롬프트 구성
- LLM 응답 생성
- 출처와 근거 반환
- 관광 카드 생성을 위한 검색 근거 연결

초급자용 설명에서는 각 단계를 쉽게 설명하지만, 실제 파일 구조를 튜토리얼 편의로 축소하지 않는다.

### 웹 화면 구조

웹 화면은 원본 앱의 실제 사용자 화면을 기준으로 한다.

- 무장애 관광 상담 화면
- 지역과 예시 선택
- 채팅형 입력
- 선택형 조건 입력
- 추천 카드
- 출처 표시
- 최신 결과 알림
- 도움말
- 개발 진단 패널

사용자 화면에는 다음 표현을 노출하지 않는다.

- `RAG 질문`
- `FastAPI tutorial result`
- `Chroma 관광 근거 검색`
- `top_k`
- `lookup_mode`
- `fallback`
- `debug`
- `pipeline`
- `parity`

이런 표현은 개발 진단 패널, 테스트, 문서에서만 사용한다.

### 전국 지역 데이터

지역 데이터는 원본 앱의 전국 지역 코드 파일을 기준으로 한다.

필수 조건:

- 전국 17개 광역 단위를 제공한다.
- 각 광역 단위는 시군구 목록을 제공한다.
- `서울 중구`, `부산 중구`, `인천 중구`처럼 같은 이름의 시군구를 구분한다.
- `강남구`, `해운대구`, `유성구`, `제주시` 같은 시군구 질문을 TourAPI 코드로 해석한다.
- 일부 샘플 지역만 넣는 방식은 금지한다.

## 작업 순서

### 1단계. 원본 기준 고정

할 일:

1. 원본 앱의 현재 구조를 읽는다.
2. 원본의 앱 구조, FastAPI 구조, RAG 구조, 웹 UI 구조를 파일 목록으로 정리한다.
3. 원본에서 가져와야 할 정적 코드와 재생성해야 할 런타임 파일을 구분한다.

완료 기준:

- 원본 기준 파일 맵이 문서화되어 있다.
- 복사 금지 대상이 정리되어 있다.
- 산출물의 목표 구조가 원본과 비교 가능하다.

### 2단계. 원본 구조 이식

할 일:

1. `project_template/app` 구조를 원본 구조와 맞춘다.
2. `project_template/frontend/web` 구조를 원본 웹 구조와 맞춘다.
3. `data/processed/tour_area_codes.json`에 전국 지역 코드를 둔다.
4. 설정 파일과 의존성 파일을 원본 실행 흐름에 맞춘다.

완료 기준:

- 원본과 같은 주요 디렉터리와 진입점이 있다.
- `/tourism-ui/` 화면 구조가 원본과 같은 사용자 화면이다.
- `/tourism/regions`가 전국 지역을 반환한다.

### 3단계. 핵심 기능 재현

할 일:

1. `/health`를 구현한다.
2. `/chat` 일반 RAG 흐름을 구현한다.
3. `/tourism/chat` 관광 상담 흐름을 구현한다.
4. TourAPI live 조회, 캐시, 준비된 자료 응답을 구현한다.
5. 세션 기반 후속 질문을 구현한다.
6. 추천 카드와 출처 표시를 원본 형식에 맞춘다.

완료 기준:

- 원본에서 쓰던 대표 질문이 같은 형태로 동작한다.
- 추천 카드가 원본 웹 화면에서 깨지지 않는다.
- 사용자 화면에 내부 구현 용어가 보이지 않는다.

### 4단계. 검증 체계 작성

할 일:

1. 원본 구조 대비 테스트를 만든다.
2. FastAPI 라우트 테스트를 만든다.
3. RAG 검색과 응답 테스트를 만든다.
4. 관광 상담 회귀 테스트를 만든다.
5. 웹 UI Playwright 테스트를 만든다.

완료 기준:

- 구조 차이를 테스트가 잡는다.
- 일부 지역만 들어간 지역 데이터는 테스트에서 실패한다.
- 사용자 화면에 내부 구현 용어가 보이면 테스트에서 실패한다.
- 원본 웹 구조와 크게 다른 UI가 들어오면 테스트에서 실패한다.

### 5단계. 튜토리얼 문서 작성

할 일:

1. 원본형 산출물을 만드는 순서를 장별로 나눈다.
2. 각 장은 “왜 필요한가”, “만들 파일”, “코드 흐름”, “실행 명령”, “확인 기준”, “자주 나는 오류”를 포함한다.
3. 어려운 용어는 한국어 풀이를 붙인다.
4. 산출물 화면을 튜토리얼용으로 바꾸지 않는다.

완료 기준:

- 초급자가 문서를 따라 원본형 앱을 만들 수 있다.
- 문서가 진행 상황 보고서처럼 보이지 않는다.
- 웹 앱은 문서와 분리된 실제 사용자용 앱으로 남아 있다.

## 금지 사항

- 산출물 웹 화면에 튜토리얼 문구를 넣지 않는다.
- 원본 앱 구조를 임의로 단순화하지 않는다.
- 일부 지역 샘플만 넣고 전국 지원처럼 말하지 않는다.
- API 응답의 사용자 문구에 내부 구현 용어를 섞지 않는다.
- 원본과 다른 화면 구조를 “튜토리얼이라서 괜찮다”고 처리하지 않는다.
- 비밀 키, 개인 절대경로, 로컬 DB, 벡터 저장소 런타임 파일을 산출물에 넣지 않는다.

## 첫 작업 체크리스트

1. 원본 앱 파일 맵을 만든다.
2. 원본 웹 UI 파일을 기준으로 `project_template/frontend/web`를 구성한다.
3. 원본 전국 지역 코드 파일을 기준으로 `data/processed/tour_area_codes.json`을 둔다.
4. FastAPI 라우터 구조를 원본과 맞춘다.
5. RAG 서비스와 관광 상담 서비스를 원본 구조대로 연결한다.
6. 사용자 화면에서 내부 구현 용어가 보이지 않는지 브라우저로 확인한다.
7. 그 다음에 문서 장을 쓴다.
