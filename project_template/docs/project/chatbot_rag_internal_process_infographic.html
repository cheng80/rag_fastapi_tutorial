1질문 입력 및 전처리

사용자 질문지역·조건 포함
입력 검증빈 문장·형식 오류 방어
대화 ID이어 묻기 확인
오타 후보띄어쓰기·표현 보정

무엇을 하나요?

  • 질문을 안전하게 처리할 수 있도록 정리
  • 대화 흐름과 오타 후보를 준비

2질문 해석

지역강남구, 중구, 제주
접근성 조건휠체어, 수유실, 점자
제외 조건시장 말고, 숙박 빼고
후속 질문더 보기, 범위 넓혀줘

무엇을 하나요?

  • AI에게 바로 맡기지 않고 추천 조건으로 분해
  • 규칙과 n-gram 보조 분류기로 문맥 판단

3지역 확정

지역 후보행정 코드 후보 생성
같은 이름 확인중구·동구·남구
지역 선택 질문서울 중구? 부산 중구?
검색 범위 확정자동 확장 금지

무엇을 하나요?

  • 모호한 지역이면 바로 추천하지 않음
  • 좁은 지역 요청에 타 지역을 섞지 않음

4Live TourAPI 우선 확인

최신 후보 조회TourAPI 먼저 시도
5초 대기빠르면 live 반환
15초 백그라운드늦은 결과 보관
승인 후 반영최신 결과 업데이트
실패 시 안전망저장 자료로 계속

무엇을 하나요?

  • live_update 모드는 TourAPI를 먼저 시도
  • 늦거나 실패하면 저장 자료를 즉시 사용

5저장 자료 안전망

메모리 캐시같은 실행 후보 재사용
SQLite 캐시관광공사 원본 응답
예비 관광 카드904개 Markdown
Chroma 검색bge-m3, top_k=40
부족 시 선택지최신 정보 더 찾기

무엇을 하나요?

  • 캐시, RAG, fallback 순서로 응답 유지
  • 5장 미만이면 자동 확장 대신 후속 선택지 제안

6추천 카드 생성

필드 정리장소명·주소·출처
근거 추출질문 조건과 맞는 문장
필수 조건점자·보조견 등 엄격 확인
순위 정렬근거 많은 카드 우선
부족 경고확인 필요 문구

무엇을 하나요?

  • 후보를 카드 형식으로 정리
  • 없는 접근성 정보는 만들지 않음

7답변 반환 및 표시

규칙 기반 요약카드 근거 설명
LLM 보조기본 OFF
JSON 응답cards, sources, warnings
화면 표시웹/Flutter 카드 렌더링

무엇을 하나요?

  • LLM은 후보 밖 정보를 만들 수 없음
  • 출처와 주의 문구를 함께 표시
